# Submission Checklist

## Engineering proof

- [ ] Real AssemblyAI voice integration works.
- [ ] Spoken request produces a stable structured proposed action.
- [ ] Real UCII identity verification works through the supported public boundary.
- [ ] Verified/no-authority request is denied.
- [ ] Denial proves executor did not run.
- [ ] Bounded delegated authority can be established through an authorized path.
- [ ] Same request succeeds only while matching authority is active.
- [ ] Exact authority can be revoked.
- [ ] Same verified identity is denied after revocation.
- [ ] Fresh authority evaluation occurs after grant and revocation.
- [ ] Provenance/evidence supports the consequential transitions.
- [ ] No alternate execution bypass exists in the normal application path.

## Security / repository hygiene

- [ ] No private keys, controller secrets, passwords, API tokens, reusable auth credentials, or wallet/payment secrets committed.
- [ ] `.env` and local secret files excluded.
- [ ] Public fixtures contain no production secrets.
- [ ] README accurately distinguishes live functionality from simulation.
- [ ] UCII core is consumed through its public boundary rather than copied into this repo.
- [ ] License remains present and appropriate.

## Judge experience

- [ ] Project value understandable within seconds.
- [ ] Voice request visible.
- [ ] Identity state visible.
- [ ] Authority state visible.
- [ ] ALLOW/DENY visible.
- [ ] Execution/non-execution visible.
- [ ] Revocation visible.
- [ ] Provenance/evidence visible without overwhelming the demo.
- [ ] Demo can be reset/repeated reliably.

## Submission assets

- [ ] Final project title.
- [ ] Short description.
- [ ] Long description.
- [ ] Public repository URL.
- [ ] Cover image/screenshots if required.
- [ ] Architecture graphic.
- [ ] Demo video.
- [ ] Presentation/pitch deck if required.
- [ ] Working demo/application URL if required.
- [ ] AssemblyAI product feedback completed from real evidence.
- [ ] Friction log updated from real evidence.

## Rules audit

- [ ] Re-read authoritative current event rules.
- [ ] Verify deadline and timezone.
- [ ] Verify team/eligibility status.
- [ ] Verify sponsor technology requirement.
- [ ] Verify required submission fields/assets.
- [ ] Verify judging access requirements.
- [ ] Verify repository visibility requirement.
- [ ] Verify video length/hosting requirement.
- [ ] Verify all claims in submission are demonstrably true.

## Final checkpoint

- [ ] Full targeted regression passes.
- [ ] Clean working tree.
- [ ] Local/remote repository parity established.
- [ ] Public repository reviewed as a judge would see it.
- [ ] Demo run completed from clean start.
- [ ] Submission completed with deadline buffer.
- [ ] Submission confirmation preserved.
